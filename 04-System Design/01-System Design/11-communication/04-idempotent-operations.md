## Summary
**Idempotency** is a property of an operation where it can be applied multiple times without changing the result beyond the initial application. In distributed systems, idempotency is crucial for handling retries safely when network failures or timeouts occur.

## Detailed Explanation

### 1. What is Idempotency?
If an operation $f(x)$ is idempotent, then $f(f(x)) = f(x)$.
*   **Example**: Setting a value to 5 is idempotent. Incrementing a value by 1 is NOT idempotent.
*   **Importance**: In a network, a request might succeed on the server but the response fails to reach the client. The client will retry. If the operation isn't idempotent, retrying might cause duplicate side effects (e.g., charging a customer twice).

### 2. HTTP Method Idempotency
*   **GET, HEAD, OPTIONS**: Idempotent (Read-only).
*   **PUT**: Idempotent (Replaces resource).
*   **DELETE**: Idempotent (Deleting twice has no further effect).
*   **POST**: **NOT** idempotent (Creates new resource).
*   **PATCH**: Usually NOT idempotent (Partial updates can be relative).

### 3. Implementing Idempotency (Idempotency Keys)
To make non-idempotent operations (like POST) safe for retries, we use **Idempotency Keys**.
*   **Mechanism**:
    1.  Client generates a unique UUID (Idempotency Key) for the request.
    2.  Client sends the key in a header (e.g., `Idempotency-Key: <UUID>`).
    3.  Server checks if it has already processed a request with that key.
    4.  If yes: Return the cached response from the first execution.
    5.  If no: Process the request, store the result + key, and return the response.

### Go Context: Distributed Retries and Locking
In Go, you often use a database or Redis to store idempotency keys.

#### Idempotency Middleware Pattern
```go
func IdempotencyMiddleware(next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		key := r.Header.Get("X-Idempotency-Key")
		if key == "" {
			next.ServeHTTP(w, r)
			return
		}

		// Check Redis/DB for existing key
		if cachedResponse, exists := checkCache(key); exists {
			w.Write(cachedResponse)
			return
		}

		// Process request and cache result
		// ...
	})
}
```

## Interview Questions
*   **Q: Why is idempotency important in a microservices architecture?**
    *   **A:** Network failures are inevitable. If a service doesn't know if its request reached the other side, it must retry. Without idempotency, retries can lead to inconsistent states or duplicate transactions.
*   **Q: Is HTTP POST idempotent? Why or why not?**
    *   **A:** No. Each POST request is intended to create a new resource or perform a non-idempotent action. Sending the same POST request twice will typically result in two resources being created.
*   **Q: How do you handle idempotency for a payment processing system?**
    *   **A:** Use an Idempotency Key (e.g., generated by the client). Before processing the payment, check if the key exists in a persistent store. If it does, return the previous status (Success/Fail). If not, proceed with the transaction atomically.
