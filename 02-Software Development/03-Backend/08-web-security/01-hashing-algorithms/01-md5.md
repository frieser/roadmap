## Summary
MD5 (Message-Digest Algorithm 5) is a widely used cryptographic hash function that produces a 128-bit hash value. While originally designed to be used as a cryptographic hash function, it has been found to suffer from extensive vulnerabilities and is no longer considered secure for cryptographic use.

## Detailed Explanation
MD5 was designed by Ronald Rivest in 1991. It is fast and efficient but fundamentally broken from a security perspective.

### Vulnerabilities
- **Collision Resistance**: MD5 is not collision-resistant. It is computationally easy to find two different inputs that produce the same MD5 hash.
- **Pre-image Attacks**: While harder than finding collisions, MD5 is also susceptible to pre-image attacks.

### Modern Use Cases
Despite being cryptographically broken, MD5 is still used for non-security purposes:
- **Checksums**: Verifying that a file hasn't been accidentally corrupted during transfer.
- **Data Deduplication**: Quickly identifying potentially duplicate files (though SHA-256 is preferred).

**WARNING**: NEVER use MD5 for storing passwords or sensitive data.

## Go Context
In Go, MD5 is available in the `crypto/md5` package.

### Example: Generating an MD5 checksum in Go
```go
package main

import (
	"crypto/md5"
	"fmt"
)

func main() {
	data := []byte("hello world")
	hash := md5.Sum(data)
	fmt.Printf("%x\n", hash)
}
```

## Interview Questions
- **Q: Why should you not use MD5 for password hashing?**
- **A:** MD5 is extremely fast, making it susceptible to brute-force attacks. More importantly, it is vulnerable to collision attacks, meaning an attacker can generate a different password that results in the same hash.

- **Q: What is a collision in hashing?**
- **A:** A collision occurs when two different input strings produce the exactly same output hash. A secure hash function should make finding such pairs computationally impossible.

- **Q: If MD5 is insecure, what is a valid use for it?**
- **A:** It can be used as a simple checksum to verify file integrity against accidental corruption (e.g., download errors), provided that there is no malicious intent involved.
