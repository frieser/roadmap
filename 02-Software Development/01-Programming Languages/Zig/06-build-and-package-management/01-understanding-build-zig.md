# Understanding build.zig

## Summary
The `build.zig` file is a Zig program that defines a dependency graph of build steps. It replaces tools like Make or CMake. It uses `std.Build` to create steps (Compile, Run, Install) and allows developers to write complex build logic using the full Zig language.

## Detailed Explanation

### The Build Graph
Zig's build system is imperative but declarative in effect. You define a graph of `Step`s.
*   **Compile Step**: Compiles code (exe, lib).
*   **Run Step**: Runs an artifact.
*   **Install Step**: Copies artifacts to `zig-out`.

### Standard Options
*   `standardTargetOptions`: Adds `-Dtarget=...` support.
*   `standardOptimizeOption`: Adds `-Doptimize=...` support (Debug, ReleaseSafe, ReleaseFast, ReleaseSmall).

### Code Example
```zig
pub fn build(b: *std.Build) void {
    const target = b.standardTargetOptions(.{});
    const optimize = b.standardOptimizeOption(.{});

    const exe = b.addExecutable(.{
        .name = "app",
        .root_source_file = b.path("src/main.zig"),
        .target = target,
        .optimize = optimize,
    });
    b.installArtifact(exe);
}
```

### Go Comparison
*   **Go**: `go build` is mostly declarative (based on directory structure). Custom logic usually goes in a Makefile or magefile.
*   **Zig**: `zig build` runs a Zig program. The build script IS code.

## Interview Questions

**Q: Why does Zig use a `.zig` file for building instead of YAML or JSON?**
**A:** It gives the build script the full power of the language (loops, logic, standard library, cross-compilation support) and ensures that the build toolchain is exactly the same as the project's language, reducing the "dual ecosystem" problem (e.g., Python code + Makefiles).

**Q: What is `b.path(...)` used for?**
**A:** It creates a `LazyPath`. In the build graph, file paths might not be known immediately (they might be generated by previous steps). `LazyPath` abstracts this, allowing steps to depend on files that don't exist yet.

**Q: What are the four standard optimization modes in Zig?**
**A:** `Debug` (safety + fast compile), `ReleaseSafe` (safety + optimizations), `ReleaseFast` (no safety + optimizations), `ReleaseSmall` (size optimizations).
