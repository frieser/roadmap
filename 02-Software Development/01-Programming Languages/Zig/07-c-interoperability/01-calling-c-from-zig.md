# Zig C Interoperability: Calling C from Zig
---

## Summary
Zig provides first-class support for C interoperability, allowing developers to directly import C header files and call C functions with zero overhead. This is primarily achieved through the `@cImport` builtin, which translates C declarations into Zig on the fly. Zig also provides C-equivalent primitive types and seamless pointer mapping to ensure ABI compatibility.

## Detailed Explanation

### 1. The `@cImport` Builtin
The `@cImport` function is the primary mechanism for bringing C declarations into Zig. It takes a block of code containing only `@cInclude`, `@cDefine`, and `@cUndef`.

```zig
const c = @cImport({
    @cDefine("_NO_CRT_STDIO_INLINE", "1");
    @cInclude("stdio.h");
    @cInclude("stdlib.h");
});
```

*   **`@cInclude`**: Adds a header file to the include path.
*   **`@cDefine` / `@cUndef`**: Defines or undefines macros for the C preprocessor before parsing the headers.
*   **Return Value**: It returns a `struct` containing all the translated C symbols (functions, types, constants).

### 2. C Primitive Types
To maintain ABI compatibility, Zig provides a set of types that match the target platform's C types:
*   `c_char`, `c_short`, `c_ushort`, `c_int`, `c_uint`, `c_long`, `c_ulong`, `c_longlong`, `c_ulonglong`.
*   `c_longdouble`: Matches the platform's `long double`.
*   `isize` / `usize`: Match `intptr_t` and `uintptr_t`.

### 3. Handling `void*` and `anyopaque`
In C, `void*` is used for generic pointers. In modern Zig (0.14+), the `anyopaque` type is used to represent C's `void`.
*   `void*` in C → `*anyopaque` or `?*anyopaque` in Zig.
*   Zig's `void` type is a zero-bit type and is **not** compatible with C's `void`.

### 4. Linking C Libraries
Importing headers is not enough; you must also link against the library's implementation.
*   **Standard Library**: Use `exe.linkLibC()` in `build.zig`.
*   **System Libraries**: Use `exe.linkSystemLibrary("z")` (for zlib) or `exe.linkSystemLibrary("sqlite3")`.

### 5. Alignment and Structs
Zig's `extern struct` guarantees a memory layout compatible with the C ABI of the target platform, including appropriate padding and alignment.

## Code Examples

### Basic C Function Call
```zig
const std = @import("std");
const c = @cImport({
    @cInclude("stdio.h");
});

pub fn main() void {
    const message = "Hello from Zig calling C!\n";
    _ = c.printf("%s", message.ptr);
}
```

### Working with C Pointers and `anyopaque`
```zig
const c = @cImport({
    @cInclude("stdlib.h");
});

pub fn main() !void {
    // malloc returns a ?*anyopaque (nullable pointer to opaque data)
    const ptr = c.malloc(100) orelse return error.OutOfMemory;
    defer c.free(ptr);
    
    // We can cast it to a specific Zig pointer type
    const byte_ptr: [*]u8 = @ptrCast(ptr);
    byte_ptr[0] = 42;
}
```

## Interview Questions

**Q: What is the difference between `@import` and `@cImport` in Zig?**
**A:** `@import` is used to import Zig modules and source files, while `@cImport` is a builtin that invokes the Zig C compiler to translate C header files into Zig code at compile-time, making C declarations available as a Zig struct.

**Q: How does Zig represent C's `void*` type?**
**A:** Zig uses `*anyopaque` (or `?*anyopaque` if nullable) to represent C's `void*`. The `anyopaque` type indicates that the size and structure of the data are unknown, similar to how `void*` functions in C.

**Q: Do you need a C compiler installed to use C libraries with Zig?**
**A:** No. Zig ships with its own C compiler (based on Clang/LLVM), so it can compile and translate C code natively without requiring an external C toolchain like GCC or MSVC.

**Q: Why should you generally use only one `@cImport` in your entire Zig project?**
**A:** Types generated by `@cImport` are unique to that specific call. If you `@cImport` the same header in two different files, Zig treats the resulting types as distinct, which can lead to type mismatch errors when passing objects between different parts of your program. It is best practice to have a single `c.zig` file that exports the required C declarations.
