## Summary
Cargo is Rust's build system and package manager. It handles downloading dependencies, compiling libraries, and managing versions via **Semantic Versioning (SemVer)**. The `Cargo.toml` file defines the project configuration and dependencies, while `Cargo.lock` ensures reproducible builds by locking dependency versions.

## Detailed Explanation

### 1. `Cargo.toml` vs `Cargo.lock`
- **`Cargo.toml`**: Written by you. Describes broad requirements (e.g., `serde = "1.0"`).
- **`Cargo.lock`**: Generated by Cargo. Records the *exact* versions used (e.g., `serde = "1.0.130"`). Always commit this for binaries; usually ignore it for libraries.

### 2. Dependency Specification
Cargo follows SemVer.
- **Caret (`^`)**: Default. `^1.2.3` allows `<2.0.0` but `>=1.2.3`. Updates strictly non-breaking changes.
- **Tilde (`~`)**: `~1.2.3` allows `<1.3.0`.
- **Wildcard (`*`)**: `*` allows anything (discouraged).
- **Git/Path**: You can point to git repos or local paths for development.

### 3. Workspaces
Workspaces allow you to manage multiple related packages (crates) in a single repository.
- They share a single `Cargo.lock` and `target/` directory.
- Defined in a root `Cargo.toml` with `[workspace]`.

## Rust Application

### Complex `Cargo.toml` Example

```toml
[package]
name = "my_app"
version = "0.1.0"
edition = "2021"

[dependencies]
# Standard registry dependency (Caret is implied)
serde = { version = "1.0", features = ["derive"] }

# Git dependency
rand = { git = "https://github.com/rust-random/rand.git", branch = "master" }

# Local dependency
my_utils = { path = "../my_utils" }

[dev-dependencies]
# Only for tests/benchmarks
criterion = "0.3"

[workspace]
members = [
    "crates/api",
    "crates/core",
]
```

## Interview Questions

### Q: Why should you commit `Cargo.lock` for binaries but not for libraries?
**A:** For binaries (applications), you want reproducible builds—everyone should run exactly the same code. For libraries, you want to ensure your code works with the widest range of compatible dependency versions that downstream users might select, so you shouldn't lock them to your specific versions.

### Q: What is the purpose of a Cargo Workspace?
**A:** Workspaces allow you to split a large project into smaller, manageable crates (libraries) while sharing a single `Cargo.lock` and build directory. This speeds up compilation (dependencies are built once for the whole workspace) and simplifies version management.

### Q: How does `^1.2.3` differ from `~1.2.3`?
**A:** `^1.2.3` (caret) allows any version that is backwards-compatible up to the next major version (`< 2.0.0`). `~1.2.3` (tilde) is more restrictive, only allowing updates to the patch version (`< 1.3.0`).
