# gRPC and Protocol Buffers

## Summary
gRPC is a high-performance RPC (Remote Procedure Call) framework developed by Google. It uses **Protocol Buffers** (Protobuf) as its Interface Definition Language (IDL) and serialization format, and runs on top of **HTTP/2**. It is the standard for inter-service communication in microservices due to its strict typing, code generation, and efficiency compared to JSON/REST.

## Detailed Explanation

### 1. Protocol Buffers (.proto)
You define your service and messages in a language-agnostic `.proto` file.
```protobuf
syntax = "proto3";
package greet;
option go_package = "./pb";

// The Service Definition
service Greeter {
  rpc SayHello (HelloRequest) returns (HelloReply) {}
}

// The Data Structures
message HelloRequest {
  string name = 1;
}

message HelloReply {
  string message = 1;
}
```

### 2. Code Generation
You use the `protoc` compiler with the Go plugin to generate the client and server code.
```bash
protoc --go_out=. --go-grpc_out=. hello.proto
```
This generates `hello.pb.go` (structs) and `hello_grpc.pb.go` (interfaces).

### 3. Implementing the Server
You implement the interface generated by `protoc`.
```go
type server struct {
    pb.UnimplementedGreeterServer
}

func (s *server) SayHello(ctx context.Context, in *pb.HelloRequest) (*pb.HelloReply, error) {
    return &pb.HelloReply{Message: "Hello " + in.GetName()}, nil
}

func main() {
    lis, _ := net.Listen("tcp", ":50051")
    s := grpc.NewServer()
    pb.RegisterGreeterServer(s, &server{})
    s.Serve(lis)
}
```

### 4. Implementing the Client
```go
conn, _ := grpc.Dial("localhost:50051", grpc.WithTransportCredentials(insecure.NewCredentials()))
defer conn.Close()

client := pb.NewGreeterClient(conn)
resp, _ := client.SayHello(context.Background(), &pb.HelloRequest{Name: "Alice"})
fmt.Println(resp.GetMessage())
```

## Interview Questions

**Q: Why is gRPC faster than REST/JSON?**
**A:**
1.  **Binary Serialization**: Protobuf is a compact binary format, much smaller and faster to parse than text-based JSON.
2.  **HTTP/2**: gRPC uses HTTP/2, which supports multiplexing (multiple requests over one connection), header compression, and server push.
3.  **Strict Typing**: No expensive runtime type checking or guessing fields.

**Q: What are gRPC Interceptors?**
**A:** Interceptors are middleware for gRPC. They allow you to intercept the execution of RPC calls on the client or server side to add logic like logging, authentication, metrics, or validation, keeping the core business logic clean.

**Q: What is the difference between `syntax = "proto2"` and `proto3`?**
**A:** `proto3` simplifies the language. It removed the `required` field rule (all fields are optional), removed default values (fields default to zero values), and added support for maps. It is the recommended version for gRPC.
