# Go Clean

## Summary
The `go clean` command removes object files, temporary executables, and cached build artifacts that are generated by `go build` or `go test` from the source tree. It is useful for resetting the project state or freeing up disk space, although Go's build cache handles cleanup automatically in most modern workflows.

## Detailed Explanation

### Usage
```bash
# Clean the current package
go clean

# Clean the entire workspace (including dependencies)
go clean -modcache
```

### What gets removed?
It removes files left by `go build`, `go test`, etc., such as:
*   Executables named after the directory (e.g., `myapp` or `myapp.exe`).
*   `_testmain.go`, `test.out`, `coverage.out` (files generated during testing).
*   It **does not** remove the Go Module cache (`$GOPATH/pkg/mod`) unless you pass the `-modcache` flag.
*   It **does not** remove the Build cache (`$GOCACHE`) unless you pass the `-cache` flag.

## Interview Questions

**Q: When should you use `go clean -modcache`?**
**A:** You should rarely need to use it. It deletes all downloaded modules from your local machine, forcing Go to re-download dependencies for every project. It is mostly used if the module cache has become corrupted or if you need to reclaim disk space.

**Q: Does `go clean` remove the binary in `$GOBIN`?**
**A:** No. `go clean` only removes files in the current source directory (like binaries created by `go build` without an output path). It does not touch installed binaries in `$GOPATH/bin`.
