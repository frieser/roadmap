## Summary
Unit testing in Terraform focuses on validating the **logic and configuration** of infrastructure modules without actually provisioning real resources. It ensures that variables are correctly processed, resource attributes are derived as expected, and conditional logic behaves correctly. With the introduction of Terraform v1.6+, native HCL testing (`.tftest.hcl`) is available, while **Terratest** remains the industry standard for Go-based, programmatic validation of `terraform plan` outputs.

## Detailed Explanation
### The Concept of Unit Testing in IaC
In traditional software, unit tests verify small, isolated pieces of code. In Terraform, a "unit" is typically a single module. Unit testing verifies the **plan** generated by Terraform rather than the result of an `apply`.

### Native Terraform Testing (v1.6+)
Terraform now supports a native testing framework using HCL. To perform a unit test, the `command = plan` attribute is used within a `run` block.
*   **Validation**: Asserts on resource attributes and outputs.
*   **Mocking (v1.7+)**: Allows mocking providers and data sources, enabling tests to run without cloud credentials.

### Terratest for Unit Testing
Terratest, a Go library developed by Gruntwork, allows developers to treat infrastructure as software. For unit tests, it uses the "Plan and Show" workflow:
1.  **Init & Plan**: Runs `terraform init` and `terraform plan -out=tfplan`.
2.  **Parse**: Converts the binary plan file into a Go struct.
3.  **Assert**: Uses Go's `testify` library to verify that the planned resources have the correct properties.

### Key Benefits
*   **Speed**: No need to wait for cloud resource provisioning.
*   **Cost**: Zero infrastructure costs as nothing is deployed.
*   **Early Detection**: Catches configuration errors in the CI/CD pipeline before any changes hit environment.

## Go (Terratest) Code Example
This example demonstrates how to use Terratest to verify that an S3 bucket module correctly applies a prefix to the bucket name during the planning phase.

```go
package test

import (
	"testing"
	"github.com/gruntwork-io/terratest/modules/terraform"
	"github.com/stretchr/testify/assert"
)

func TestS3BucketModuleUnit(t *testing.T) {
	t.Parallel()

	terraformOptions := &terraform.Options{
		// Path to the Terraform module to test
		TerraformDir: "../modules/s3-bucket",

		// Variables to pass to the module
		Vars: map[string]interface{}{
			"bucket_prefix": "unit-test",
		},

		// Save the plan to a file for introspection
		PlanFilePath: "terraform.tfplan",
	}

	// Run 'terraform init' and 'terraform plan'
	// InitAndPlanAndShowWithStruct returns a Go struct representing the plan
	plan := terraform.InitAndPlanAndShowWithStruct(t, terraformOptions)

	// Resource address in the Terraform code
	resourceAddress := "aws_s3_bucket.this"

	// 1. Verify the resource exists in the plan
	terraform.RequirePlannedValuesMapKeyExists(t, plan, resourceAddress)
	
	// 2. Extract the planned values for the resource
	plannedResource := plan.ResourcePlannedValuesMap[resourceAddress]
	
	// 3. Assertions: Verify the bucket name starts with the prefix
	bucketName := plannedResource.AttributeValues["bucket"].(string)
	assert.Contains(t, bucketName, "unit-test")
}
```

## Interview Questions
**Q: What is a "unit test" in the context of Terraform?**
**A:** A unit test in Terraform validates the configuration logic of a module by inspecting the `terraform plan` output. It ensures that for a given set of inputs, the module produces the expected resource attributes without actually deploying them to a cloud provider.

**Q: How does Terraform v1.7+ facilitate unit testing without cloud credentials?**
**A:** Version 1.7 introduced **native mocking** support in `.tftest.hcl`. You can define `mock_provider` blocks to simulate provider behavior and return static values for data sources, allowing tests to run completely offline or in environments without access to cloud APIs.

**Q: Why use Go (Terratest) instead of the native HCL testing framework?**
**A:** Terratest is preferred when you need complex logic (loops, regex, conditional branching), when you want to use a unified testing language (Go) across your entire stack (K8s, Docker, Cloud), or when you need to perform advanced post-plan operations that HCL doesn't support.

**Q: What is the purpose of `terraform.InitAndPlanAndShowWithStruct` in Terratest?**
**A:** It automates the workflow of initializing the directory, running a plan, saving it to a file, and then running `terraform show -json` to convert that plan into a structured Go object that can be easily asserted against.
