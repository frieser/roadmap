# Docker Volumes CLI

## Summary

Docker volumes are the preferred mechanism for persisting data generated by containers. They provide Docker-managed storage that exists independently of container lifecycle, offers better performance than bind mounts on some platforms, and can be shared between containers. The volume CLI commands allow creating, inspecting, backing up, and removing volumes.

## Detailed Explanation

### Creating Volumes

```bash
# CREATE NAMED VOLUME
docker volume create mydata

# CREATE VOLUME WITH LABELS
docker volume create --label env=production --label app=myapp mydata

# CREATE VOLUME WITH DRIVER OPTIONS
docker volume create --driver local --opt type=tmpfs --opt device=tmpfs --opt o=size=100m temp-volume

# CREATE MULTIPLE VOLUMES
docker volume create db_data cache_data logs_data

# CREATE VOLUME WITH SPECIFIC SIZE
# Not directly supported via CLI
# Size depends on volume driver and usage

# QUIET CREATION
docker volume create -q mydata  # No output
```

### Listing Volumes

```bash
# LIST ALL VOLUMES
docker volume ls
# DRIVER    VOLUME NAME
# local     mydata
# local     db_data
# local     7f4a3b2c1d0e9f8a7b6c5d4e3f2a1b0c9d8e7f6a

# LIST WITH FORMATTING
docker volume ls --format "table {{.Driver}}\t{{.Name}}\t{{.Mountpoint}}"

# LIST ONLY DRIVER
docker volume ls --format "{{.Driver}}"

# LIST ONLY NAMES
docker volume ls --format "{{.Name}}"

# LIST FILTERED VOLUMES
docker volume ls --filter "label=env=production"
docker volume ls --filter "name=mydata*"

# DETAILED INSPECTION
docker volume inspect mydata
# Shows full JSON configuration

# INSPECT SPECIFIC FIELDS
docker volume inspect --format '{{.Mountpoint}}' mydata
# /var/lib/docker/volumes/mydata/_data

docker volume inspect --format '{{.Options}}' mydata
# {}

docker volume inspect --format '{{.Labels}}' mydata
# map[env:production app:myapp]
```

### Inspecting Volume Content

```bash
# LIST VOLUMES AND MOUNTPOINTS
docker volume ls -q | xargs -I {} docker volume inspect --format '{{.Name}}: {{.Mountpoint}}'

# VIEW FILES IN VOLUME
# Docker volumes are stored at /var/lib/docker/volumes/<volume_name>/_data
sudo ls -la /var/lib/docker/volumes/mydata/_data

# COUNT FILES IN VOLUME
sudo find /var/lib/docker/volumes/mydata/_data -type f | wc -l

# CALCULATE VOLUME SIZE
sudo du -sh /var/lib/docker/volumes/mydata/_data

# VIEW VOLUME USAGE
# Docker doesn't track per-volume usage
# Use filesystem tools to check size
du -sh /var/lib/docker/volumes/
```

### Removing Volumes

```bash
# REMOVE SPECIFIC VOLUME
docker volume rm mydata

# REMOVE MULTIPLE VOLUMES
docker volume rm mydata db_data cache_data

# FORCE REMOVE (IN USE VOLUMES)
docker volume rm -f mydata

# REMOVE ALL UNUSED VOLUMES
docker volume prune
# Removes all volumes not mounted by any container

# REMOVE ALL UNUSED WITH CONFIRMATION
docker volume prune

# REMOVE UNUSED OLDER THAN TIME
docker volume prune --filter "until=24h"
# Volumes not used in last 24 hours

# REMOVE ANONYMOUS VOLUMES ONLY
docker volume prune --filter "dangling=true"
# Removes only unnamed (anonymous) volumes

# REMOVE ALL VOLUMES (DANGEROUS)
docker volume ls -q | xargs -I {} docker volume rm
# BE VERY CAREFUL - deletes ALL volumes including used ones
```

### Backing Up Volumes

```bash
# BACKUP VOLUME TO TAR ARCHIVE
docker run --rm \
  -v mydata:/data \
  -v $(pwd):/backup \
  alpine tar czf /backup/mydata-backup.tar.gz -C /data .

# BACKUP VOLUME SPECIFIC DIRECTORY
docker run --rm \
  -v mydata:/data \
  -v $(pwd):/backup \
  alpine tar czf /backup/config-backup.tar.gz -C /data ./config

# BACKUP MULTIPLE VOLUMES
docker run --rm -v mydata:/data -v db_data:/data -v $(pwd):/backup alpine sh -c \
  'tar czf /backup/all-data.tar.gz -C /data -C /data .'

# COMPRESSED BACKUP
docker run --rm -v mydata:/data -v $(pwd):/backup alpine tar cjf /backup/mydata-backup.tar.xz -C /data .

# BACKUP TO REMOTE (using SSH)
ssh user@server "docker run --rm -v /remote/path:/backup -v /local/path:/backup alpine tar czf -backup.tar.gz -C /backup ."
```

### Restoring Volumes

```bash
# RESTORE FROM TAR ARCHIVE
docker volume create mydata_restored
docker run --rm \
  -v mydata_restored:/data \
  -v $(pwd):/backup \
  alpine tar xzf /backup/mydata-backup.tar.gz -C /data .

# RESTORE TO NEW VOLUME
docker run --rm -v mydata:/data -v $(pwd):/backup alpine tar xzf backup.tar.gz -C /data .

# RESTORE SPECIFIC DIRECTORY
docker run --rm -v mydata:/data -v $(pwd):/backup alpine tar xzf backup.tar.gz -C /data ./app

# RESTORE WITH OVERWRITE CONFIRMATION
echo "This will overwrite existing data. Continue? (y/n)"
read CONFIRM
[ "$CONFIRM" = "y" ] && docker run --rm -v mydata:/data -v $(pwd):/backup alpine tar xzf backup.tar.gz -C /data .
```

### Volume Drivers and Plugins

```bash
# LOCAL DRIVER (DEFAULT)
docker volume create --driver local myvolume
# Standard Docker-managed volumes

# NFS VOLUME DRIVER
docker volume create --driver local \
  --opt type=nfs \
  --opt device=192.168.1.100:/exported/path \
  --opt o=addr=192.168.1.1,rw \
  nfs-volume

# CIFS/SMB VOLUME DRIVER
docker volume create --driver local \
  --opt type=cifs \
  --opt device=//server/share \
  --opt o=username=user,password=pass \
  cifs-volume

# REX-RAY (S3) PLUGIN
docker plugin install rexray/s3fs
docker volume create -d rexray/s3fs mybucket
# Uses AWS S3 as volume storage

# SSHFS (REMOTE FILESYSTEM)
docker volume create --driver local \
  --opt type=sshfs \
  --opt device=user@server:/remote/path \
  --opt o=password \
  sshfs-volume

# VIEW INSTALLED PLUGINS
docker plugin ls

# LIST DRIVER CAPABILITIES
docker info | grep -A 10 "Volume Driver"
```

### Volume Maintenance

```bash
# CLEANUP OLD VOLUMES (MANUAL)
# Remove volumes from deleted projects
docker volume ls --filter "label=project=oldproject"

# VERIFY VOLUME INTEGRITY
# Check if volume is actually being used
docker ps --format '{{.Mounts}}' | grep mydata

# CHECK VOLUME ORPHANS
# Find volumes without containers
docker volume ls -q | xargs -I {} docker volume inspect --format '{{.Name}}' | \
  while read volume; do
    CONTAINER=$(docker ps -q --filter volume=$volume)
    if [ -z "$CONTAINER" ]; then
      echo "Orphaned: $volume"
    fi
  done

# FIND LARGE VOLUMES
du -sh /var/lib/docker/volumes/* | sort -rh | head -20

# VOLUME SIZE AUDIT
for volume in $(docker volume ls -q); do
  SIZE=$(sudo du -s /var/lib/docker/volumes/$volume/_data 2>/dev/null)
  echo "$volume: $SIZE"
done
```

### Cross-Host Volume Backup

```bash
# BACKUP ALL VOLUMES TO HOST
for volume in $(docker volume ls -q); do
  docker run --rm \
    -v $volume:/data \
    -v $(pwd)/backup/$volume:/backup \
    alpine tar czf /backup/$volume.tar.gz -C /data .
done

# RESTORE ALL VOLUMES FROM HOST
for archive in backup/*.tar.gz; do
  VOLUME_NAME=$(basename "$archive" .tar.gz)
  docker volume create ${VOLUME_NAME}_restored
  docker run --rm \
    -v ${VOLUME_NAME}_restored:/data \
    -v $(pwd)/backup:/backup \
    alpine tar xzf /backup/$archive -C /data .
done
```

## Interview Questions

### Q1: What is a Docker volume and how is it different from a bind mount?
**A:** A Docker volume is a persistent storage mechanism managed by Docker, stored in `/var/lib/docker/volumes/`. It exists independently of container lifecycle and can be shared between containers. A bind mount maps a host directory into a container, depends on host filesystem structure, and is not portable.

### Q2: How do you create a Docker volume?
**A:** Use `docker volume create <volume-name>`. This creates a named volume managed by Docker. You can add labels with `--label` for organization, or specify a driver (like NFS) with `--driver` and options.

### Q3: What does `docker volume prune` do?
**A:** `docker volume prune` removes all volumes not currently mounted by any container. This includes anonymous volumes (no name) and named volumes that are orphaned. Add `-f` to skip confirmation. Use `--filter` to prune based on time (`until=24h`) or labels.

### Q4: How do you back up a Docker volume?
**A:** Create a temporary container that mounts the volume and a host directory, then use `tar` to create an archive: `docker run --rm -v mydata:/data -v $(pwd):/backup alpine tar czf backup.tar.gz -C /data .`. For database-specific backups, use database tools like `pg_dump` instead.

### Q5: How do you restore a Docker volume from a backup?
**A:** Create a new volume, mount both the new volume and the backup archive to a temporary container, then extract: `docker run --rm -v new_volume:/data -v $(pwd):/backup alpine tar xzf backup.tar.gz -C /data`. For databases, use `docker exec -i postgres psql dbname < backup.sql` to restore database-specific data.

### Q6: What is a volume driver in Docker?
**A:** A volume driver determines where and how volume data is stored. The default `local` driver stores on the host filesystem. Other drivers support external storage systems like NFS (`--opt type=nfs`), CIFS/SMB, or cloud storage through plugins like REX-Ray for S3.

### Q7: How do you share a volume between multiple containers?
**A:** Mount the same volume in multiple containers: `docker run -v mydata:/app container1` and `docker run -v mydata:/data:ro container2`. One container can write while others read. Named volumes are the recommended way to share data between containers.

### Q8: How do you check which volumes are actually being used by containers?
**A:** Use `docker ps --format '{{.Mounts}}'` to see mounted volumes for each container, then compare with `docker volume ls`. Or check each volume: `docker volume inspect <volume>` and see which containers reference it in their Mounts field.
