## Summary
The **Filesystem Hierarchy Standard (FHS)** defines the directory structure and directory contents in Linux distributions. Maintained by the Linux Foundation, it ensures that users and software can predict the location of installed files and directories. Understanding this hierarchy is fundamental for system administration, software development, and navigating any Linux-based environment efficiently.

## Detailed Explanation

The Linux filesystem is organized in a tree-like structure, starting from the **root directory** (`/`). Below are the primary directories defined by the FHS and their purposes:

### Core System Directories
- **`/` (Root)**: The top-level directory. Every file and directory in the system starts here.
- **`/bin`**: Contains essential user command binaries that must be available when the system is mounted in single-user mode (e.g., `ls`, `cp`, `cat`). In many modern distros, this is a symlink to `/usr/bin`.
- **`/sbin`**: Essential system binaries used primarily by the root user for system maintenance (e.g., `iptables`, `fdisk`, `reboot`). Often a symlink to `/usr/sbin`.
- **`/boot`**: Stores static files needed to boot the system, such as the Linux kernel (`vmlinuz`), initrd images, and GRUB configuration.
- **`/lib`**: Contains essential shared library images and kernel modules required by binaries in `/bin` and `/sbin`.

### Configuration and User Data
- **`/etc`**: The heart of system configuration. It contains host-specific configuration files for all programs (e.g., `/etc/passwd`, `/etc/fstab`, `/etc/hosts`). It does not contain binaries.
- **`/home`**: Contains user home directories for regular users (e.g., `/home/username`). This is where users store their personal files and settings.
- **`/root`**: The home directory for the **root** user. It is separate from `/home` to ensure the root user can still log in even if `/home` is on a different partition that fails to mount.

### Variable and Temporary Data
- **`/var`**: Holds "variable" data files that are expected to grow in size, such as system logs (`/var/log`), mail spools (`/var/mail`), and database files (`/var/lib`).
- **`/tmp`**: A place for temporary files created by users and applications. Files here are usually deleted upon reboot.
- **`/run`**: A modern directory (tmpfs) used for system state information since the last boot (PIDs, sockets, etc.).

### Hardware and Kernel Interfaces
- **`/dev`**: Contains device nodes that represent hardware components or virtual devices (e.g., `/dev/sda` for a hard drive, `/dev/null`).
- **`/proc`**: A virtual filesystem providing process and kernel information (e.g., `/proc/cpuinfo`, `/proc/meminfo`).
- **`/sys`**: Another virtual filesystem that provides an interface to kernel objects, attributes, and configuration.

### Optional and Add-on Software
- **`/usr`**: The "User System Resources" directory. It contains the majority of user utilities and applications. It has its own hierarchy (e.g., `/usr/bin`, `/usr/lib`, `/usr/local`).
- **`/opt`**: Reserved for the installation of add-on application software packages (e.g., Google Chrome or third-party tools).
- **`/mnt` / `/media`**: Used for mounting filesystems. `/media` is typically for removable media (USB, CD), while `/mnt` is for temporary manual mounts.

### UsrMerge Note
In modern Linux distributions (like Fedora, Arch, and newer Debian/Ubuntu), the "UsrMerge" initiative has moved all binaries and libraries into `/usr`, making `/bin`, `/sbin`, and `/lib` symbolic links to their counterparts in `/usr`.

## Interview Questions

**Q: What is the purpose of the `/etc` directory?**
**A:** The `/etc` directory contains host-specific system-wide configuration files for the operating system and applications. It is strictly for configuration data and should not contain executable binaries.

**Q: Where would you look for system log files in a Linux system?**
**A:** System log files are typically located in the `/var/log` directory. For example, `syslog` or `messages` (depending on the distro) and service-specific logs like `nginx/error.log` are stored there.

**Q: What is the difference between `/bin` and `/usr/bin`?**
**A:** Traditionally, `/bin` contained essential binaries needed for system booting and repairing in single-user mode, while `/usr/bin` contained non-essential binaries for general user use. In modern "merged-usr" systems, `/bin` is usually a symbolic link to `/usr/bin`.

**Q: What are `/proc` and `/sys` directories?**
**A:** Both are "virtual" or "pseudo" filesystems. They don't exist on disk but are generated by the kernel in memory. `/proc` focuses on process information and kernel statistics, while `/sys` provides a more structured view of hardware devices and kernel drivers.

**Q: Why is `/root` located outside of `/home`?**
**A:** To ensure that the root user can always log in and perform emergency maintenance, even if the `/home` directory (which might be on a separate partition or network drive) fails to mount.
