# WC (Word Count)

## Summary

**wc** (word count) is a Unix command that counts lines, words, characters, and bytes in text files. It's a fundamental tool for text analysis, used to measure file sizes, count occurrences, and process text data programmatically. wc reads from files or stdin, making it useful in pipelines.

## Detailed Explanation

### WC Output Format

```bash
# Default output format
wc filename.txt
# Output:  10  25 150 filename.txt
#          |    |   |    |
#          |    |   |    +- filename (or stdin if piped)
#          |    |   +------- characters (bytes)
#          |    +----------- words
#          +--------------- lines
```

| Column | Meaning | Option |
|--------|---------|---------|
| **Column 1** | Lines | `-l` |
| **Column 2** | Words | `-w` |
| **Column 3** | Bytes (characters) | `-c` or `-m` |

### Basic Usage

```bash
# Count lines, words, bytes in single file
wc file.txt

# Count in multiple files
wc file1.txt file2.txt file3.txt
# Output:
#   10  25 150 file1.txt
#    5  12  80  file2.txt
#   15  37 230 total

# Read from stdin
echo "hello world" | wc
# Output:  1  2  12

# Count from command output
ls -la | wc
# Output:  10  90 800
```

### WC Options

| Option | Description |
|---------|-------------|
| `-l` | Count lines |
| `-w` | Count words |
| `-c` | Count bytes |
| `-m` | Count characters (handles multibyte) |
| `-L` | Length of longest line |
| `--files0-from=F` | Read filenames from file F, NUL-terminated |

### Line Counting (-l)

```bash
# Count lines
wc -l file.txt
# Output:  10 file.txt

# Count lines from command output
ps aux | wc -l
# Output: 15 (number of processes)

# Count non-empty lines
grep -v "^$" file.txt | wc -l
# Output:  5 (only non-empty lines)

# Count lines matching pattern
grep "error" log.txt | wc -l
# Output: 12 (lines containing "error")
```

### Word Counting (-w)

```bash
# Count words
wc -w article.txt
# Output:  350 article.txt

# Count words in multiple files
wc -w *.txt

# Count words from stdin
cat essay.txt | wc -w

# Count unique words (with sort/uniq)
tr -s '[:space:]' '\n' < file.txt | sort | uniq | wc -l
```

### Byte/Character Counting (-c, -m)

```bash
# Count bytes
wc -c file.txt
# Output:  1500 file.txt

# Count characters (handles UTF-8 correctly)
wc -m file.txt

# Difference between bytes and characters
echo "áéíóú" | wc -c
# Output:  15 (3 bytes per char for UTF-8)

echo "áéíóú" | wc -m
# Output:  5 (5 characters)

# Find files larger than 1MB
find . -type f -exec wc -c {} \; | awk '$1 > 1048576'
```

### Longest Line (-L)

```bash
# Find length of longest line
wc -L file.txt
# Output: 80

# Check if any line exceeds 80 characters
if [ $(wc -L < file.txt) -gt 80 ]; then
    echo "File has line longer than 80 chars"
fi

# Find files with long lines
wc -L *.txt
# Output:
#  80 file1.txt
# 120 file2.txt  <- potential issue
```

### Practical Examples

#### 1. Count Lines in Code

```bash
# Count lines of code (LOC)
wc -l *.py *.js
# Output:
#   120 app.py
#    45 main.js
#   165 total

# Count excluding blank lines
grep -v "^$" *.py | wc -l
```

#### 2. File Size Statistics

```bash
# Analyze directory
wc -c *.log
# Output:
#   1500 access.log
#   3200 error.log
#   4700 total

# Sort by size
wc -c *.log | sort -n
```

#### 3. Count Specific Patterns

```bash
# Count lines containing error
grep "ERROR" log.txt | wc -l

# Count unique IP addresses in access log
cut -d' ' ' -f1 access.log | sort | uniq | wc -l

# Count function definitions in Python
grep "def " *.py | wc -l
```

#### 4. Pipeline Usage

```bash
# Count files in directory
ls | wc -l

# Count running processes
ps aux | wc -l

# Count words in stdin
echo -e "line1\nline2\nline3" | wc -l
# Output:  3

# Count output of find
find . -name "*.txt" | wc -l
# Output: 25 (number of .txt files)
```

#### 5. File Validation

```bash
# Check file is not empty
if [ $(wc -l < file.txt) -gt 0 ]; then
    echo "File has content"
fi

# Ensure line doesn't exceed limit
if [ $(wc -L file.txt) -le 120 ]; then
    echo "Lines are within limit"
fi
```

#### 6. Log Analysis

```bash
# Count error types in log
grep "ERROR" app.log | wc -l    # Error count
grep "WARN" app.log | wc -l     # Warning count
grep "INFO" app.log | wc -l     # Info count

# Count unique users in access log
cut -d' ' ' -f1 access.log | sort | uniq | wc -l

# Daily line count
grep "2024-01-09" app.log | wc -l
```

### WC with Files0-From

```bash
# Read filenames from file
find . -name "*.txt" -print0 > files.txt
wc -l --files0-from=files.txt

# Process NUL-terminated filenames (handles spaces in names)
find . -name "*.txt" -print0 | wc -l --files0-from=-
```

### Advanced WC Patterns

```bash
# Pattern 1: Count total LOC in project
find . -name "*.py" | xargs wc -l | tail -1
# Output:   1250 total

# Pattern 2: Largest files by line count
wc -l *.txt | sort -nr | head -5
# Output: Top 5 files with most lines

# Pattern 3: File statistics table
printf "%-20s %8s %8s\n" "Filename" "Lines" "Words"
wc -lw *.txt | awk '{printf "%-20s %8s %8s\n", $2, $1, $3}'

# Pattern 4: Compare file counts
wc -l file1.txt file2.txt | awk '
    NR == 1 { f1 = $1 }
    NR == 2 { f2 = $1 }
    END { print "File1:", f1, "File2:", f2, "Diff:", f2 - f1 }
'
```

### WC in Scripts

```bash
#!/bin/bash

# Check file has at least N lines
file="$1"
min_lines="$2"

lines=$(wc -l < "$file")

if [ "$lines" -lt "$min_lines" ]; then
    echo "ERROR: $file has only $lines lines (need $min_lines)"
    exit 1
fi

echo "OK: $file has $lines lines"
```

### WC vs Alternatives

| Tool | Purpose | Different from WC |
|-------|---------|-----------------|
| **wc** | Count lines, words, bytes | Built-in, simple |
| **nl** | Number lines | Doesn't count |
| **cat** | Display files | Doesn't count |
| **grep -c** | Count matching lines | Only pattern-based |
| **awk 'END {print NR}'** | Count lines | More powerful but complex |

### WC Performance

```bash
# Large files: wc is very fast
# Uses mmap for efficiency

# Compare with slower alternatives
# Fast:
wc -l largefile.txt

# Slower (for comparison):
while read line; do count++; done < largefile.txt
echo $count
```

### Common WC Issues

```bash
# Issue 1: Filename in output when reading from pipe
echo "test" | wc
# Output:  1  1  5

# Solution: Use < to remove filename
wc < <(echo "test")
# Output:  1  1  5

# Issue 2: Newlines at end of files
# Some editors don't add trailing newline
wc -l file.txt
# Might report 1 less than expected

# Solution: Add newline or use other methods
# Issue 3: Unicode characters
wc -c vs wc -m
echo "ñ" | wc -c  # 2 bytes
echo "ñ" | wc -m  # 1 character

# Use -m for character count in UTF-8 files
```

## Interview Questions

**Q: What does wc output format mean?**
**A:** Default output: `lines words bytes filename`. Example: ` 10  25 150 file.txt` means 10 lines, 25 words, 150 bytes. When reading from stdin, filename is omitted.

**Q: How do you count only lines with wc?**
**A:** Use `wc -l file.txt`. This outputs only the line count: ` 10 file.txt`. To get just the number without filename: `wc -l < file.txt` or `wc -l file.txt | awk '{print $1}'`.

**Q: What is the difference between wc -c and wc -m?**
**A:** `-c` counts bytes, `-m` counts characters. For ASCII, they're identical. For UTF-8 or other multibyte encodings, characters may be fewer than bytes (e.g., "ñ" is 1 character, 2 bytes in UTF-8). Use `-m` for character count, `-c` for file size.

**Q: How do you find the longest line in a file?**
**A:** Use `wc -L file.txt` which outputs the length of the longest line. Example: `wc -L file.txt` → `80` means the longest line has 80 characters.

**Q: How do you count files in a directory with wc?**
**A:** `ls | wc -l` counts files listed by ls. For recursive: `find . -type f | wc -l`. For specific pattern: `find . -name "*.txt" | wc -l`.

**Q: How do you count lines matching a pattern with wc?**
**A:** Pipe grep output to wc: `grep "pattern" file.txt | wc -l`. This counts lines containing the pattern. For multiple patterns: `grep -E "pattern1|pattern2" file.txt | wc -l`.

**Q: How does wc handle files with no trailing newline?**
**A:** wc counts lines based on newlines. If a file has content but no trailing newline, `wc -l` may report 0 or 1 less than expected. This is by design - wc counts newline characters, not content lines.
