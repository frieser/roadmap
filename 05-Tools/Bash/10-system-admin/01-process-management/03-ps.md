# ps (Process Status)

## Summary

The `ps` command reports information about running processes. It's essential for system monitoring, troubleshooting, and process management. Understanding `ps` output and options helps identify resource usage, find process IDs, and debug system issues.

## Detailed Explanation

### Basic Usage

```bash
# Current shell processes
ps

# All processes (BSD style)
ps aux

# All processes (Unix style)
ps -ef

# All processes with full format
ps -eF
```

### Common Options

```bash
# BSD style (no dash)
ps aux          # All processes, user-oriented format
ps axo pid,cmd  # Custom columns

# Unix style (with dash)
ps -e           # All processes
ps -f           # Full format
ps -u username  # Processes by user
ps -p 1234      # Specific PID
```

### Understanding ps aux Output

```bash
ps aux
# USER       PID %CPU %MEM    VSZ   RSS TTY      STAT START   TIME COMMAND
# root         1  0.0  0.1 168936 12340 ?        Ss   Jan01   1:23 /sbin/init
# │            │   │    │     │     │   │        │    │       │    └── Command
# │            │   │    │     │     │   │        │    │       └── CPU time used
# │            │   │    │     │     │   │        │    └── Start time
# │            │   │    │     │     │   │        └── Process state
# │            │   │    │     │     │   └── Terminal
# │            │   │    │     │     └── Resident memory (KB)
# │            │   │    │     └── Virtual memory (KB)
# │            │   │    └── Memory percentage
# │            │   └── CPU percentage
# │            └── Process ID
# └── Owner

# Process states (STAT column):
# R - Running
# S - Sleeping (interruptible)
# D - Disk sleep (uninterruptible)
# T - Stopped
# Z - Zombie
# < - High priority
# N - Low priority
# s - Session leader
# + - Foreground process
```

### Filtering Processes

```bash
# By user
ps -u root
ps -U apache

# By name (use grep or pgrep)
ps aux | grep nginx
pgrep -a nginx         # Better alternative

# By PID
ps -p 1234
ps -p 1234,5678,9012

# By terminal
ps -t pts/0

# Exclude grep from results
ps aux | grep [n]ginx   # Brackets prevent self-match
```

### Custom Output Format

```bash
# Select specific columns
ps -eo pid,ppid,user,%cpu,%mem,cmd

# Useful columns:
# pid    - Process ID
# ppid   - Parent PID
# user   - Username
# %cpu   - CPU percentage
# %mem   - Memory percentage
# vsz    - Virtual memory
# rss    - Resident memory
# stat   - Process state
# start  - Start time
# time   - CPU time
# cmd    - Command with arguments
# comm   - Command name only

# Sorted output
ps aux --sort=-%cpu | head -10    # Top CPU
ps aux --sort=-%mem | head -10    # Top memory
ps aux --sort=-rss | head -10     # Top RSS
```

### Process Trees

```bash
# Show parent-child relationships
ps auxf                   # Forest format
ps -ejH                   # Hierarchical
pstree                    # Tree view
pstree -p                 # With PIDs
pstree -u username        # User's processes
```

### Practical Examples

```bash
# Find process by port (combine with other tools)
lsof -i :8080
ss -tlnp | grep 8080

# Find zombie processes
ps aux | awk '$8 ~ /Z/'

# Count processes per user
ps -eo user | sort | uniq -c | sort -rn

# Long-running processes
ps -eo pid,etime,cmd --sort=-etime | head

# Memory-hungry processes
ps -eo pid,rss,cmd --sort=-rss | head -10

# Check if process is running
if ps -p $PID > /dev/null 2>&1; then
    echo "Process $PID is running"
fi
```

## Interview Questions

**Q: What is the difference between `ps aux` and `ps -ef`?**
**A:** Both show all processes. `ps aux` is BSD style (no dash, includes CPU/MEM %). `ps -ef` is Unix/POSIX style (with dash, includes PPID). Both are valid; choose based on preference or system.

**Q: How do you find the top memory-consuming processes?**
**A:** Use `ps aux --sort=-%mem | head -10` or `ps -eo pid,%mem,cmd --sort=-%mem | head -10`. The `-` before `%mem` sorts descending.

**Q: What does a zombie process (Z state) mean?**
**A:** A zombie is a finished process whose exit status hasn't been collected by its parent. It uses no resources except a PID. Fix by having the parent call `wait()` or killing the parent process.
