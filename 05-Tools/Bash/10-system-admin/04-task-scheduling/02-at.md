## Summary
The `at` command allows you to schedule a command to execute **once** at a specific time in the future. It is different from `cron`, which is for recurring tasks. It requires the `atd` service to be running.

## Detailed Explanation

### Scheduling
*   **Absolute Time**: `at 5pm`, `at 10:00 07/31/23`.
*   **Relative Time**: `at now + 1 hour`, `at now + 5 minutes`.

### Interaction
1.  Type `at <time>`.
2.  Type commands (one per line).
3.  Press `Ctrl+D` (EOT) to save and exit.

### Management
*   `atq`: List pending jobs.
*   `atrm <job_id>`: Remove a pending job.
*   `at -c <job_id>`: View the content of a pending job.

## Go-Specific Context/Examples

In Go, for one-off delayed execution within a running application, use `time.AfterFunc`.

### Analogy
*   **Bash**: `echo "run_task.sh" | at now + 5 min`
*   **Go**:
    ```go
    time.AfterFunc(5 * time.Minute, func() {
        runTask()
    })
    ```
    *Note*: Go's timer is in-memory. If the app restarts, the task is lost. `at` persists tasks to disk.

## Interview Questions

**Q: Where is the output of an `at` job sent?**
**A:** Like cron, it is emailed to the user (local mail spool). You should redirect output: `command > /tmp/log 2>&1`.

**Q: Can you restrict who uses `at`?**
**A:** Yes, via `/etc/at.allow` and `/etc/at.deny` files.

**Q: What happens if the computer is off at the scheduled time?**
**A:** Unlike `anacron`, `at` does not guarantee execution if the system was down. The job might be missed.
