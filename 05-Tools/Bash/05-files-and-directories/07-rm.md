# rm (Remove)

## Summary

The `rm` command removes files and directories. It's powerful and dangerous - deleted files don't go to a trash bin and are generally unrecoverable. Understanding options like `-r`, `-f`, and `-i` is crucial for safe file management.

## Detailed Explanation

### Basic Usage

```bash
# Remove file
rm file.txt

# Remove multiple files
rm file1.txt file2.txt file3.txt

# Remove with wildcard
rm *.log
rm test_*
```

### Common Options

```bash
# -r (or -R): Recursive - remove directories
rm -r directory/

# -f: Force - no prompts, ignore nonexistent
rm -f file.txt
rm -rf directory/    # Dangerous but common

# -i: Interactive - prompt before each removal
rm -i *.txt

# -I: Prompt once before removing > 3 files
rm -I *.log

# -v: Verbose
rm -v file.txt
# removed 'file.txt'
```

### Safety Practices

```bash
# ALWAYS use -i for important operations
alias rm='rm -i'

# Preview what would be deleted
ls *.tmp
rm -i *.tmp

# Use trash-cli instead of rm
# (install: apt install trash-cli)
trash-put file.txt
trash-list
trash-restore

# Never run: rm -rf /  or  rm -rf /*
# Modern rm has --preserve-root by default
```

### Dangerous Patterns to Avoid

```bash
# DANGEROUS: Variable could be empty
rm -rf "$DIR/"    # If DIR is empty, becomes rm -rf /

# SAFER: Use parameter expansion
rm -rf "${DIR:?Variable not set}/"

# DANGEROUS: Space in wrong place
rm -rf / tmp      # Deletes root!

# SAFER: Quote variables
rm -rf "$DIR"
```

### Common Patterns

```bash
# Remove all except certain files
rm -v !(keep.txt|important.doc)  # Needs shopt -s extglob

# Remove files older than N days
find . -type f -mtime +30 -delete

# Remove empty directories
find . -type d -empty -delete

# Interactive cleanup
find . -name "*.log" -exec rm -i {} \;
```

## Interview Questions

**Q: What does `rm -rf` do?**
**A:** `-r` removes directories recursively (including contents). `-f` forces removal without prompts and ignores nonexistent files. Together, they delete everything in the target without confirmation - very powerful and dangerous.

**Q: How can you protect against accidental rm?**
**A:** Use `rm -i` (interactive prompts), set `alias rm='rm -i'`, use trash-cli instead, or implement safe-rm. Always verify commands with `ls` first before removing.
