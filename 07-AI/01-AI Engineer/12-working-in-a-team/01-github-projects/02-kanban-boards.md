## Summary
A **Kanban Board** is a visual layout in GitHub Projects that organizes work into columns (e.g., "Todo", "In Progress", "Done"). It's excellent for managing a continuous flow of tasks in an AI development team.

## Detailed Explanation
### **AI Team Kanban Workflow**
- **Backlog**: New research ideas, requested features, reported bugs.
- **Triage**: Identifying which tasks are feasible and high priority.
- **In Progress (Research)**: Tasks currently being explored (e.g., "Test new tokenizer").
- **In Progress (Implementation)**: Writing the actual code for a feature.
- **Review**: Code review and model performance verification.
- **Done**: Merged and deployed.

### **Board Customization**
- **Grouping**: Group cards by "Assignee" or "Priority".
- **Filtering**: Show only "Bug" cards or cards related to a specific "Model".
- **Limit WIP**: Although not strictly enforced by GitHub, teams can set limits on how many cards are in "In Progress" to prevent burnout and focus on completion.

## Interview Questions
**Q: What are the benefits of using a Kanban board over a simple list of tasks?**
**A:** A Kanban board provides immediate visual feedback on the state of the project, helps identify bottlenecks (e.g., too many cards in "Review"), and makes it easy to move tasks between stages by dragging and dropping.

**Q: How can you use "Groups" in a GitHub Board to manage an AI team?**
**A:** You can group by "Assignee" to see exactly what each team member is working on, or by "Priority" to ensure that high-impact model fixes are being addressed first.
