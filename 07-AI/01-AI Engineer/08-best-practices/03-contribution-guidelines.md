## Summary
**Contribution Guidelines** (`CONTRIBUTING.md`) is a document that explains how others can contribute to your project. For AI Engineer projects, it defines the standards for code quality, model testing, and documentation.

## Detailed Explanation
### **Key Sections for an AI Project**
- **Getting Started**: How to set up the environment (e.g., `conda` vs `pip`, GPU requirements).
- **Code Style**: Following PEP8 for Python, using `black` or `ruff` for formatting.
- **Testing Requirements**: Instructions on how to run unit tests and what performance metrics must be reported for model changes.
- **PR Process**: How to name branches, write commit messages, and request reviews.
- **Data Policy**: Guidelines on how to handle datasets (e.g., "Do not upload raw data to the repo").
- **Communication**: Links to GitHub Discussions, Discord, or Slack for the project.

### **Importance of CONTRIBUTING.md**
- **Scalability**: Allows new team members to onboard quickly without constant guidance.
- **Quality Control**: Ensures that every contribution meets the minimum standard for performance and maintainability.
- **Transparency**: Clear rules on who can merge code and how decisions are made.

## Interview Questions
**Q: What should an AI Engineer look for in a project's CONTRIBUTING.md before making a PR?**
**A:** They should look for the coding standards, the testing suite requirements, the preferred branch naming convention, and whether there are specific requirements for reporting model metrics (like a benchmark log).

**Q: How does a strong contribution guide help an open-source AI project grow?**
**A:** It lowers the barrier to entry for new contributors by providing clear instructions, while simultaneously maintaining high code quality and ensuring that the project doesn't fragment into inconsistent styles.
